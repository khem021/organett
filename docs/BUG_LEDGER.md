# Bug ledger

Every defect found in the audit, in the order it was fixed. Each was reproduced by a failing test **before** the fix; the test named in the last column is the one that failed first and now guards it. Rows marked **Decision** changed a business rule: I picked the conservative option (block with a clear message, never silently change money or stock) and flag it here so it can be reversed.

Test file names are in `tests/Feature/`. "Evidence" says how the problem was shown before fixing: *ran* = a failing test or throwaway probe against the unfixed code; *read* = established from the code and framework source.

## Mistakes of my own that testing caught

Recorded because they say something about how the checks are layered:

* **B-18, first attempt.** My MySQL-compatibility fix broke the Reports page on PostgreSQL (a 500 for every farm user). The suite did not notice because that test had only run on SQLite; the live browser pass did. Fixed, and the report test now runs on PostgreSQL too.
* **Password-field component.** My first conversion of the sign-in, sign-up and reset forms swallowed other fields (the email on the reset page; the farm name, name and email on sign-up) and every test still passed. It was spotted in a screenshot. `AuthPagesTest` now asserts each form carries every field its controller validates.
* **Hidden "Actions" column headers** are absolutely positioned; with no positioned ancestor they escaped the scrolling table wrapper and made every list page scroll sideways by 400 to 600 px on a phone. Caught by the browser interaction checks; tables are now positioned containers.

## Checked and found sound (guards added, nothing to fix)

Reproduced against the current code and held by a test, so they stay that way:

* **Routes and roles:** `RouteAccessTest` requests every GET route as a guest, farm staff, farm admin, platform owner, impersonating owner, a deactivated user, and members of pending, suspended and archived farms. No route returned a 500, and every role got exactly the expected 200 / 403 / 404 / redirect. All 67 application routes resolve to an existing controller method, and every `view()` call resolves to a file.
* **Tenant isolation:** another farm's batch, stock item, order and receipt return 404 by id; list pages and the search box show none of its rows.
* **Escaping:** text such as `<script>alert(1)</script> & "quotes" 💡 Ñandú 李雷` is escaped on the customer list, order list, order page, printed receipt and activity log; emoji and non-Latin text round-trip intact. There is no `{!! !!}` in any view.
* **Zero, negative and over-limit quantities** are refused for payments, order weight, price, stock withdrawals; **overpaying** an order is refused; **very long free text** (≈6,600 characters in a note) is accepted and over-long fields give validation errors.
* **Empty farm:** every member and admin page, and every export period, opens for a farm with no data.
* **Batch rules:** a batch with harvest records cannot be deleted; one whose harvests are gone can; two farms may share a batch code; a duplicate within a farm is refused.
* **Month boundary:** harvest "this month" does not include the same month of another year.

## Not changed on purpose (open decisions and limits)

| Item | Why it is left alone |
|---|---|
| **Farm staff can delete** customers, batches, inventory, harvest records and individual payments, and adjust stock (only `/users`, `/settings`, `/activity-logs`, `/reports/export` are admin-only). | Who may delete is a policy choice for the owner, not a bug. The dangerous money cases are now blocked (B-07, B-08). *Decision needed.* |
| First order of a year under two simultaneous requests can still collide on the order number. | There is no row to lock before the first order exists; it needs a retry or a counter table. Rare, and untestable without real concurrency. |
| MySQL compatibility is by reading only. | MySQL is not installed here. The one PostgreSQL-only construct found (`NULLS LAST`) is fixed in B-18; nothing else was found, but nothing was run on MySQL. |
| Impersonation: if the viewed farm is suspended or the viewed user deactivated mid-visit, the operator lands on the login page and no `impersonate_end` entry is written. | Cosmetic audit gap; fixing it means special-casing the session teardown. |
| `AccountRecovery` clears sessions only with the `database` session driver. | Production uses it; the local `.env` uses `file`, where it silently clears nothing. |
| CSP still allows `'unsafe-inline'` scripts. | Needs the inline handlers moved to bundled files (UI phase). |
